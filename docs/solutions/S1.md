# S1 : solution commentée

Ordre de lecture conseillé. Chaque fichier contient des commentaires qui expliquent le pourquoi.

1. `frontend/src/app/edition.model.ts` : le type `EditionStatus` (union), l'interface `Edition`, `export`, `string | null`.
2. `frontend/src/app/edition-card/edition-card.ts` : `input.required`, `computed`, `Record<K, V>`, `imports: [DatePipe]`.
3. `frontend/src/app/edition-card/edition-card.html` : `edition()` (lecture du signal), `| date`, `@if / @else`, `[class]`.
4. `frontend/src/app/app.ts` et `app.html` : déclaration du composant dans `imports`, données en dur dans un `signal`, `[edition]="edition()"`.
5. `frontend/src/app/edition-card/edition-card.spec.ts` : `setInput`, un test par critère d'acceptation.

## Ce qui change par rapport à la première tentative

| Avant | Après | Pourquoi |
|---|---|---|
| `interface Edition` | `export interface Edition` | Sans `export`, les autres fichiers ne voient pas le type |
| `startTime: Date` | `startTime: string` | L'API envoie du texte ISO 8601 |
| `EditionCard` jamais utilisée | `imports: [EditionCard]` + `<app-edition-card>` | Un composant standalone déclare ceux qu'il utilise |
| Pas d'`input()` | `input.required<Edition>()` | Le parent envoie la donnée à la carte |
| Gabarit Angular de 344 lignes | `app.html` de 5 lignes | Le gabarit était un exemple à supprimer |

## À refaire sans regarder

Supprimez `edition-card.ts` et `edition-card.html`, puis réécrivez-les de mémoire. Comparez ensuite avec la solution. Ce qui vous échappe est ce qu'il faut relire.

## Questions du ticket

1. `type` union ou `interface` : une union liste des valeurs possibles (`'STARTED' | 'COMPLETED' | 'FAILED'`), une interface décrit la forme d'un objet (ses champs).
2. `edition()` avec parenthèses : un signal est une fonction. L'appeler lit sa valeur, et Angular sait ainsi quels morceaux de template mettre à jour.
3. `ng serve` : il recompile à chaque sauvegarde et recharge le navigateur.
